# v2.0.0

**Status:** commits `7eb4e40`–`6cf62f8` on `MASTER`. Everything up to `d7448e8` was pushed on 2026-11-15. The rest (`386f08a`–`6cf62f8`) is committed but **not pushed yet**. On push, replace this line with the date.

The first official release. It combines the earlier working versions 0.1.0, 0.2.0, 0.2.1, 0.2.2 and 0.2.3.

## Before and after you deploy

- **Render must have `CLIENT_SECRET` set.** The server refuses to start without it.
- **Redeploy the server on Render by hand**, then open `https://demacia-bom-app-n2ag.onrender.com/api` and check that it answers `{"status":"online"}`.
- **The server packages must stay in the root `package.json`.** Render installs only the root one. (Removing them once crashed the server with `Cannot find package 'dotenv'`.)
- **Rebuild and hand out the extension** (`npm run package:extension`). The extension doesn't update by itself: changes reach the panel only after a new build or zip and a reload in `chrome://extensions`.
- **Publish again every top assembly that reuses a sub-assembly under different parents** (see "Correct quantities for reused sub-assemblies"). Check work orders made from them earlier: they may be short on parts.
- **⚠ The next Publish BOM permanently deletes** the existing STL and Parasolid files of vendor parts already published (Drive's delete skips the trash).

## Extension

### Publish BOM

- **Won't overwrite newer work.** Before saving, it checks whether anyone published any of the items after your copy loaded, including edits made on the website. If so, it stops, names the items, and asks you to press Refresh BOM. Nothing is changed.
- **Saves from the bottom up:** parts first, then sub-assemblies, then the top assembly. If an item fails, the assemblies that contain it aren't saved either, so no record links to one that doesn't exist. The message names the item that failed. Items that did save are kept, and publishing again retries the rest.
- **A server error no longer looks like "not published".** If the server is down or slow while a BOM loads, you get an error. Before, every item quietly showed as unpublished, and the next Publish overwrote the saved records.

### Correct quantities for reused sub-assemblies

- **A sub-assembly used under several parents is listed, and saved, under each of them.** Before, it was listed only under the first parent, so Publish BOM left it out of the other parents' saved BOMs, and work orders under-counted every part inside it. Each parent now saves its own quantity of the sub-assembly, and the sub-assembly itself is saved once.

### Vendor and standard parts

- **Vendor parts and sub-assemblies are always standard parts.** Anything with an Onshape Vendor set is shown with Standard part ticked and locked, with no STL and no Parasolid, and saved with engineer "Standard Part". A vendor sub-assembly is one bought item: its insides aren't loaded, and work orders count it as one item.
- **"Hide standard parts" also hides vendor parts,** and the count next to the toggle includes them.

### Tables

- **No more ghost or multiplying rows.** A part used in several sub-assemblies has the same ID each time, and the table used that ID to tell rows apart, so rows were left behind or multiplied on every update. Rows are now told apart by their parent as well; the stored IDs are unchanged.
- **Search finds parts inside a shared sub-assembly under every parent,** not just the first one.
- **Red cells explain themselves.** Hover over or click into a red (problem) cell to see why.
- **You are the default engineer.** The panel reads your Onshape name once. Empty Engineer cells of made items show it in grey, and Publish BOM saves it for items without an engineer.

### Loading and reliability

- Switching Onshape tabs stops the previous load, so it no longer mixes into the assembly you switched to.
- Images load at most 4 at a time, rate-limited requests are retried, and a request with no answer for 30 seconds shows as failed.
- Refresh BOM is disabled while the parts of a sub-assembly are still loading, so rows can't appear twice.
- An empty sub-assembly is treated as an assembly, not a part, so it no longer causes failed STL/Parasolid exports.
- The Demacia button no longer stays hidden after a temporary error (it retries after 2, 5 and 15 seconds), and it's placed less often, using less CPU.
- Saved Onshape links use the Onshape address the tab is actually on, which fixes links for enterprise accounts.
- Edits are saved to the local copy once you pause, not on every keystroke. When storage is full, the oldest saved assemblies are removed first. Saved copies from older versions are discarded once.
- The image cache keeps at most 3000 images, none older than 60 days.
- Telemetry counts requests correctly when two operations overlap.

## Website

### New

- **Standard Parts page.** Bought items (Onshape Standard Content, vendor parts, items marked standard, and sub-assemblies marked standard) have their own page in the sidebar instead of appearing in Search Parts and on the BOMs page. Parts saved only inside a bought sub-assembly count as standard too, unless they're also used in an assembly the team makes. Nothing in the database is changed; BOM detail pages, links and work orders still show these items.
- **Export a work order's parts to PDF.** On a work order, **Export PDF** (next to "Showing N of M parts") makes a printable list of the parts the table shows, with the current filters and sort order: a large image, name, catalogue number and quantity for each. Choose "Save as PDF" in the print dialog.
- **Search Parts lists sub-assemblies** with a "Sub-assembly" badge; clicking one opens its BOM page. It shows "Loading…", the actual error, or "No parts have been published yet" instead of always saying "Nothing found".
- **Right-clicking a sub-assembly offers both "Go to Subassembly BOM" and "Show Part Data".** A standard sub-assembly opens its part details; one the team makes opens a read-only summary with an Open Onshape button.

### Safer saves

- **Editing a cell on a BOM page saves only what you changed,** so it no longer undoes someone else's newer changes. Quick edits are sent together, failed saves are listed per part, and a failed part's changes are sent again with its next edit.
- **Saves report failures, and local testing no longer writes to production.** Saving a part shows "Saved ✓"; a failed cell save shows a "Change not saved" banner.
- **Invalid numbers are rejected instead of saved as 0.** Quantity and revision take whole numbers; other number cells take plain decimals with a dot (e.g. "1.5"). An empty cell still means 0.
- **Part details lock only bought parts** (with a vendor, or Onshape Standard Content), the same parts the extension locks.

### Fixes

- No stale data when switching quickly between BOMs or work orders.
- Right-click and avatar click on a BOM page open the right part, also when the table is sorted, filtered, collapsed, or the Avatar column was moved.
- BOM and work-order pages show the saved part name, even long ones or ones with an underscore.
- "Linked BOMs" in part details loads faster.
- The last column of every table fills the spare width.
- A work order built from a BOM that contains itself shows an error instead of loading forever.
- Tables pick up column changes, React warnings in dropdown cells are gone, and arrow keys only move within the same table.
- Links open in a new tab safely (`noopener`), and only `http(s)` links are opened.
- The theme toggle applies to the BOM pages too, and a missing-stylesheet error on every page load is gone.

## Server

- **Refuses to start without `CLIENT_SECRET`.** Before, a missing secret left the whole API open.
- **Drive access is limited to the team's three folders** (images, STL, Parasolid). All 63 stored file references were checked on 2026-11-15 and are inside them.
- **Saving a whole work order no longer resets other people's per-part progress.** Parts added to a work order later start at 0 made, not 1.
- Saves accept only plain field values: database commands, dotted paths and server-owned fields are ignored. Two people creating the same record at once no longer causes an error.
- `GET /api` answers with a health status.
- Drive file requests return proper error codes (404 unknown file, 502 Drive problem) and the file's real type.
- Production types and statuses are looked up by their real ID.
- Internal error details are no longer sent to clients.
- Settings are read in one place (`server/config.ts`), and `npm run build` in `server/` type-checks the server. Unused code and packages were removed.
