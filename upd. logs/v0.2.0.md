# v0.2.0

**Unreleased.** Committed on `MASTER` (`e9ea512`–`689111d`), not pushed yet.

The high- and medium-priority fixes, mostly making Publish BOM safe when something fails or when several people work on the same assembly.

## Before you deploy

- **Render must have `CLIENT_SECRET` set.** The server now refuses to start without it.
- **Hand out the new extension zip** (`npm run package:extension`). The Publish safety checks only apply to the new version.
- **Bump `package.json` to `0.2.0`** before you push, and add the date at the top of this file.

## Extension

- **Publish BOM won't overwrite newer work.** Before saving, it checks whether anyone published any of the items after your copy loaded. That includes edits made on the website. If so, it stops, names the items, and asks you to press Refresh BOM. Nothing is changed.
- **Publish BOM saves from the bottom up:** parts first, then sub-assemblies, then the top assembly. If an item fails, the assemblies that contain it aren't saved either, so no record links to one that doesn't exist. The message names the item that failed. The items that did save are kept, and publishing again retries the rest.
- **A server error no longer looks like "not published".** If the server is down or slow while a BOM loads, you now get an error. Before, every item quietly showed as unpublished, and the next Publish overwrote the saved records.
- **Switching Onshape tabs stops the previous load,** so it no longer mixes into the assembly you switched to.
- **Images load at most 4 at a time.** If Onshape rate-limits a request, it is retried. A request that gets no answer for 30 seconds shows as failed, so other images keep loading.
- Saved copies from older versions are discarded once. The first time you open each assembly, it loads fresh from Onshape.

## Website

- No changes of their own. The server changes below apply to the website too.

## Server

- **Refuses to start without `CLIENT_SECRET`.** Before, a missing secret left the whole API open.
- **Drive access is limited to the team's three folders** (images, STL, Parasolid). A check of all 63 stored file references on 2026-11-15 found them all inside those folders, so existing records are not affected. Reading a file still needs no secret (images are shown with `<img>` tags); that waits for the authentication decision.
- **Saving a whole work order no longer resets other people's per-part progress.** The part list is written only when the work order is created.
- Parts added to a work order later start at 0 made, not 1.
- Saves accept only plain field values: database commands, dotted paths and server-owned fields (IDs, timestamps) are ignored. Two people creating the same record at once no longer causes an error.
- An unused Drive upload lock was removed.

## Docs

- The README was rewritten, with a guide for team members and one for developers.
