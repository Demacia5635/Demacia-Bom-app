# Extension v2.2.0

**Unreleased.** Committed on `MASTER` (`f482e8d`–`7cd6231`), not pushed or built yet. Replaces [v2.0.0](../2.0.0/v2.0.0.md).

The extension shares `package.json` with the website. Set it to `2.2.0` before building the zip. (These changes were first logged as 2.1.1. That version was never built, so they're part of 2.2.0.)

## Before handing it out

- **Redeploy the server on Render first** (server v2.2.0). Until then, Publish BOM from this version saves everything except the part sizes, without any error.

## New

- **Show part sizes.** A **Show size** checkbox (next to "Hide standard assemblies") adds a read-only **Size** column after Name, e.g. `25 × 8 × 8 mm`. It shows each made part's bounding box from Onshape, longest side first, so you can tell spacers and shafts apart. Bought parts (standard, vendor or marked standard) and assemblies get no size. The browser remembers the checkbox. (`4e9f2bd`)
  - Saved sizes show at once. A size is read from Onshape only when there's none yet or the part's Part Studio changed since it was saved, only while the box is ticked, and at most 4 at a time. (`7cd6231`)
  - **Publish BOM saves each made part's size** for the website, reading it from Onshape only when it's missing or out of date. It never blanks a size that's already saved.
  - A BOM copy that hasn't been refreshed can show an old size until you press Refresh BOM. Publish BOM checks it again anyway.
  - The box is aligned with the Part Studio's axes, so a part drawn at an angle shows bigger than it really is.

## Changes

- **Clicking the toolbar icon or the in-page "BOM" button again closes the panel.** Before, it only opened it. Closing it this way is the same as closing it by hand. On Chrome before version 141 the panel is closed by switching it off for that tab; the next click opens it again. (`30b4530`)
- **Problem cells are easier to see.** Red (problem) cells have a stronger red tint and a thicker red underline. Frozen columns now show the tint too: before, their background hid it. The "N problems" button and the top-assembly warning are a deeper red instead of pink. (`f482e8d`)
- **A failed check of the Onshape page says why.** When the extension can't read the open Onshape document, the warning in `chrome://extensions` now includes Onshape's own reason, not just "Onshape API 403". A 403 (no access) or 404 (not found) is no longer retried 3 times, so there's one warning instead of four. The Demacia button still stays hidden on that page. (`24d5d60`)
- **A column you show appears next to its neighbour,** not at the far right, even after you've dragged columns around. (`420e89f`, shared with the website)

## Known problems

- The cause of the 403 on some documents isn't fixed yet. This version only shows more about it.

## Not tested yet

- None of it has run in the real panel in Onshape. That includes the panel toggle in Chrome and Firefox (on Firefox, the in-page button may not be allowed to close the sidebar), whether Onshape's bounding-box request returns what's expected, and the Show size checkbox in both themes. Only the type check and the builds pass.
