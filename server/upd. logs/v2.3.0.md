# Server v2.3.0

**Unreleased.** Committed on `MASTER` (`9e2894e`, `ee857da`, `14d82ed`), not pushed yet.

## Before you deploy

- **Redeploy on Render together with website 2.3.0.** Until the server has this version, merging parts on a work order fails with a "not found" error.

## Changes

- **Work orders can hold CNC jobs** (`cncGroups`): parts cut together in one CNC run that share one G-code link. They're stored apart from the work order's parts, so a part's own links and progress are never changed, and old work orders work as before. (`9e2894e`)
- **New route `POST /db/workOrder/id/:id/cncGroup`** creates, changes or dissolves one job in a single database update, so two people merging at once don't overwrite each other.
  - Every part must be in that work order.
  - A part joining a job leaves its old one, and a job left with fewer than 2 parts is removed.
  - Bad input gets 400, and an unknown work order gets 404.
- Saving a whole work order ignores `cncGroups`, so an old copy of the page can't undo a merge. (`9e2894e`)
- **The route can change only a job's links,** without resending its parts. If the job was removed by someone else in the meantime, it answers 409 instead of quietly saving nothing. (`ee857da`, `14d82ed`)

## Known problems

- Merging doesn't update the work order's "last updated" time.

## Not tested yet

- Not run against a real database. The update is only type-checked.
