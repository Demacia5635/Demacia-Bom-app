# Server v3.0.0

**Pushed:** 2026-11-17 23:18 (`c41ab23` already on 2026-11-17 22:52). Combines the earlier 2.2.0 and 2.3.0. Render must still be redeployed by hand.

## Before you deploy

- **Redeploy on Render before handing out extension 3.0.0, and when website 3.0.0 is pushed.** Until the server has this version, part sizes sent by Publish BOM are dropped without an error, and merging parts on a work order fails with "not found".

## Changes

- **Parts have a `size` field:** text like `25 × 8 × 8 mm`, the part's bounding box in Onshape. Publish BOM fills it, and the website shows it. Existing parts get it the next time they're published. (`c41ab23`)
- **Work orders can hold CNC jobs** (`cncGroups`): parts cut together in one CNC run that share one G-code link. They're stored apart from the work order's parts, so a part's own links and progress are never changed, and old work orders work as before. (`9e2894e`)
- **New route `POST /db/workOrder/id/:id/cncGroup`** creates, changes or dissolves one job in a single database update, so two people merging at once don't overwrite each other.
  - Every part must be in that work order.
  - A part joining a job leaves its old one, and a job left with fewer than 2 parts is removed.
  - Bad input gets 400, and an unknown work order gets 404.
- Saving a whole work order ignores `cncGroups`, so an old copy of the page can't undo a merge. (`9e2894e`)
- **The route can change only a job's links,** without resending its parts. If someone else removed the job meanwhile, it answers 409 instead of quietly saving nothing. (`ee857da`, `14d82ed`)

## Known problems

- Merging doesn't update the work order's "last updated" time.
