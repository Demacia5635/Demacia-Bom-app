# Server v5.1.0

**Pushed:** 2026-11-23. Render must be redeployed by hand. A medium update (+0.1.0).

## Before you deploy

- `ADMIN_SECRET` must still be set on Render (it is since 5.0.0): it now also protects deleting parts in no assembly.
- **The first start builds one new database index** (BOMs by their parts' IDs). It builds by itself; no data changes.

## New

- **`GET /api/db/health`: every problem in the parts and BOMs**, for the website's `#/health` page. Read-only (2 database reads). The catalog-number rules are the same code the extension and website use. (`36301b4`, `db5a72c`, `ad5f895`)
  - **Errors** (a failure in the code): `PART_MISSING`, `SUB_ASSEMBLY_MISSING`, a BOM pointing to a record that isn't saved.
  - **Warnings** (keeps an item out of work orders): bad catalog number, missing material, engineer, image, STL or Parasolid, duplicate assembly catalog numbers or names, an assembly saved from two workspaces, and parts in no assembly. Bought items are exempt from the made-part checks.
- **`GET /api/db/part/orphans`:** the parts no BOM uses, newest first, with how many of their Drive files nothing else uses. For `#/orphans`. (`0c58630`)
- **`POST /api/db/part/orphans/delete` (admin):** deletes parts no BOM uses (1–200 per request), re-checking each right before deleting it, so a part in use is never deleted. Their Drive files that no other record uses go to Drive's trash (kept 30 days); shared files stay. Each delete writes one server-log line with who, the trashed files and the whole record, so it can be restored by hand. Without the right `x-admin-secret` it answers 404. (`ec3cb95`)
- **After a publish, parts it removed from a BOM are deleted when no BOM uses them anymore,** in the same background run as the Drive sort (60 s after the publish's last save), before the sort. Only parts that publish removed are considered; a part moved to another sub-assembly in the same publish is kept. Same trash and log rules as above; the run's report and log line say "cleanup: N deleted, M kept". A failing cleanup doesn't stop the sort. (`13b7afb`)

## Changes

- **Deleting a part by ID refuses parts in use** (`409 PART_IN_USE`). The extension's one use (removing an assembly's leftover standard-part record) still works. Each delete is logged. Deleting by Onshape key is turned off (405); nothing used it. (`85290da`)
- Two type fixes, no behaviour change; the server now type-checks with 0 errors. (`0c7a09c`)
- `server/package-lock.json`'s version was brought in line with `server/package.json`.

## Not tested yet

- Nothing has run against the real database or Drive; everything was tested with stand-in data (including a full publish with a moved and a removed part, through the real save code and the real 60 s wait).
- **Watch the first publish after deploying** that removes a part: about a minute later, Render's log should show the cleanup line.
