# Server v5.0.0

**Unreleased.** On branch `fix/serv`, not on `MASTER` yet. A large update (+1.0.0).

## Before you deploy

- **Set `ADMIN_SECRET` on Render** (any long random text, kept off the website and extension). It protects the Drive-sorting route.
- After the redeploy, run the sorting **dry run** first and read its report, then the real run (commands below, once the route is done).

## New

- **Drive files are sorted into assembly folders.** Inside each type folder (Images, STL, x_t) there's a folder per assembly, named by its catalog number (or name) and nested like the BOM, e.g. `Images/2714-0000/2714-1000/2714-1100/`. (`6bb7c66`, `f10f0c3`)
  - A part used in several assemblies goes in the first one it's used in: top-level assemblies oldest first, each walked with its own parts before its sub-assemblies. An assembly's own picture goes in its own folder.
  - Bought items go in a `Standard parts` folder in each type folder; a bought sub-assembly gets the same nesting inside it.
  - Files are only **moved**: their IDs and links don't change, nothing is deleted or copied, and nothing in the database changes. Folders are reused, never duplicated. Running it twice moves nothing the second time.
- **Admin routes to run the sort** (protected by `ADMIN_SECRET`; without it they don't exist): `POST /api/drive/organize` (`{ "dryRun": true }` for a dry run that only lists the planned moves and any clashing catalog numbers), `GET /api/drive/organize/<jobId>` for a run's progress and report, and `GET /api/drive/organize` for the last 10 runs. (`f10f0c3`)
- **After every Publish BOM**, the server sorts that assembly's files in the background, 60 seconds after the last save. It never slows down or fails the publish. (`26fff07`)

## Blocked saves

- **Saving an assembly is refused (nothing is saved) when its folder would clash** (`c84616a`):
  - the same Onshape assembly is already published from **another workspace or version** of the document. Its BOM is kept for one workspace only: "<catalog> (<name>) was already published from another workspace or version of this Onshape document. Its BOM is kept for one workspace only: publish it from the workspace it was first published from. Nothing was saved."
  - **another assembly already has the catalog number**: "Catalog number 2714-1000 is already used by another assembly, "Intake". Give this assembly its own catalog number in Onshape, then publish again. Nothing was saved."
  - two assemblies under the same parent have no catalog number and the same name.
- Saving the same record again is fine. Clashes that already exist block those assemblies from being published again until they're fixed; the sort's dry run lists them.
- The first start builds indexes on catalog numbers and Onshape document + element (no data changes).

## How to run the first sort

In PowerShell write `curl.exe`; in Git Bash write `curl`. Replace `<CLIENT>` with the `VITE_CLIENT_SECRET` value, `<ADMIN>` with the `ADMIN_SECRET` value, `<JOB>` with the `jobId` from the reply.

1. Dry run (moves nothing):
   `curl.exe -X POST "https://demacia-bom-app-n2ag.onrender.com/api/drive/organize" -H "x-client-secret: <CLIENT>" -H "x-admin-secret: <ADMIN>" -H "Content-Type: application/json" -d "{\"dryRun\":true}"`
2. Check it until `"status"` is `"done"`, and read the moves, skips and clashes:
   `curl.exe "https://demacia-bom-app-n2ag.onrender.com/api/drive/organize/<JOB>" -H "x-client-secret: <CLIENT>" -H "x-admin-secret: <ADMIN>"`
3. Fix any duplicate catalog numbers it lists (in Onshape), then the real run:
   `curl.exe -X POST "https://demacia-bom-app-n2ag.onrender.com/api/drive/organize" -H "x-client-secret: <CLIENT>" -H "x-admin-secret: <ADMIN>" -H "Content-Type: application/json" -d "{}"`
4. Recent runs: `curl.exe "https://demacia-bom-app-n2ag.onrender.com/api/drive/organize" -H "x-client-secret: <CLIENT>" -H "x-admin-secret: <ADMIN>"`

A full run takes roughly 10–20 minutes per 3000 files. Keep checking its status now and then: a sleeping free Render instance or a redeploy stops it, and starting it again just continues.
